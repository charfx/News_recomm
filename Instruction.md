# Projet pédagogique, vision professionnelle
Référence : docs/cahier-des-charges-actualites.md et docs/architecture-conteneurs.md
Règles pour CHAQUE fonctionnalité :
1. Avant de coder : expliquer le concept, le cas d'usage et la conception (schéma, choix, alternatives écartées). Attendre mon accord.
2. Implémenter par petites étapes, un conteneur ou un module à la fois.
3. Code commenté sur le "pourquoi", pas seulement le "quoi".
4. Après : écrire docs/learn/<module>.md (concept, formules, exemple chiffré, limites, comment tester) et des tests.
5. Les interactions viennent uniquement de nos écouteurs, jamais de logs importés.
6. Ne jamais pousser, merger ou supprimer sans mon accord.
